Improve the existing Corporate Actions Impact Copilot repository. Do not build a separate application or replace the existing backend unnecessarily. First inspect the current code, routes, API, database and synthetic demo data.

The main objective is to redesign the UI so the POC presents one clear corporate-action operations journey. The current application contains the right capabilities, but they are spread across too many tabs and the user cannot immediately understand where a case is, what has been completed or what must happen next.

This is an internal operations tool for analysts, reviewers and operations managers. It is not a customer-facing product.

PRODUCT SCOPE

The POC must demonstrate how an operations team can:

1. Receive a corporate-action notice.
2. Identify and classify the event.
3. Extract important terms with source evidence.
4. Validate or correct the extracted terms.
5. identify affected securities, funds, accounts and positions.
6. Calculate the expected cash or security impact.
7. Capture an election when the event requires a decision.
8. Apply maker-checker approval.
9. Generate downstream tasks.
10. Create a simulated instruction when required.
11. Compare expected and actual settlement.
12. identify reconciliation breaks.
13. Retain a complete audit trail.

Do not position this as a Rights Issue Copilot. It is a Corporate Actions Impact Copilot.

The synthetic data should include:

- Cash dividend
- Rights issue
- Stock split
- Bonus issue or stock dividend
- Tender offer
- Merger or acquisition

At least two cases must be fully interactive:

- One voluntary event, such as a rights issue
- One mandatory event, such as a cash dividend

This is important because the POC must demonstrate that the workflow changes according to the corporate-action type.

CORE UX PRINCIPLE

The user should never need to work out which tab to open.

Every case must clearly answer:

- What event is this?
- Which funds and accounts are affected?
- What is the current stage?
- What has already been completed?
- What is blocked?
- What is the next action?
- Who owns the next action?
- When is it due?
- What evidence supports the result?
- What approval is required?

Replace the existing flat nine-tab structure with a visible case journey.

CASE JOURNEY

Use this horizontal lifecycle at the top of every event:

Notice → Validate → Exposure → Impact → Decision → Execute → Reconcile & Close

Every stage must have one of these states:

- Completed: green check
- Current: blue highlighted stage
- Blocked: lock icon with explanation
- Attention required: amber warning
- Not required: grey skipped state
- Future: neutral state

The stepper must be clickable, but the current stage should open automatically.

The workflow must be conditional.

For a mandatory cash dividend:

Notice → Validate → Exposure → Impact → Decision not required → Instruction not required → Reconcile & Close

For a voluntary rights issue:

Notice → Validate → Exposure → Impact → Election and approval → Simulated instruction → Reconcile & Close

For a tender offer or merger with options, display the relevant decision and approval workflow.

Do not show an active Election step when no election is required. Clearly mark it “Not required for this mandatory event.”

- Cash dividend
- Rights issue

- Bonus issue
- Tender offer
- Merger

Each card should show:

- Event type
- Mandatory or voluntary
- Issuer

Allow the user to preview the synthetic notice before processing it.

If real PDF parsing is not implemented, do not call this an arbitrary PDF upload. Do not classify an event by checking whether its filename contains the word “rights.”

The correct POC flow is:

Select sample notice → Process notice → Create case for review → Open the Validate stage

Replace “Create reviewed case” with “Create case for review,” because the analyst has not reviewed it yet.
