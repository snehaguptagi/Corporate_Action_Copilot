Six independent fixes. None of them changes the API contract.

1. The documented start command cannot work. scripts/dev.mjs starts the API on
   `process.env.API_PORT ?? "8080"`, but artifacts/corporate-actions-copilot/vite.config.ts
   line 76 hardcodes the /api proxy to 'http://127.0.0.1:3001'. So `pnpm dev`,
   exactly as the README instructs, gives ECONNREFUSED on every API call.

   Unify on ONE convention: have vite.config.ts read the API port from
   `process.env.API_PORT` with the same default as dev.mjs, make
   artifacts/api-server/package.json's `dev:local` script use API_PORT too, and
   update the README so the documented ports match reality. Do not leave two
   defaults in two files.

2. artifacts/corporate-actions-copilot/src/pages/TasksList.tsx compares
   `task.status === 'OPEN'` at lines 88 and 96. The server emits title-case
   "Open" / "Resolved" (corporate-actions-v2.ts around line 155). Both
   comparisons are permanently false, so EVERY Resolve button is disabled and
   every open task renders a green "success" badge reading "Open".

   Fix the comparison. Dashboard.tsx:179 and EventWorkbench.tsx:580 already
   handle the casing correctly — match whichever of those two patterns is
   cleaner, and use it consistently. Check the whole frontend for any other
   uppercase status comparison against a title-case server value.

3. Empty numeric inputs submit zero because the guards are no-ops.
   EventWorkbench.tsx:132 does `Number(electionQuantities[impact.id] ?? "")`
   and `Number("")` is 0, not NaN, so `Number.isNaN(quantityElected)` never
   fires: an empty quantity box posts quantityElected: 0 under a toast saying
   "Election submitted for approval."

   Line 154 has the identical bug for reconciliation, where it is worse — an
   empty "Actual cash" field posts actual: 0, which the server correctly
   classifies as a full settlement break.

   Guard on the raw string being empty or non-numeric BEFORE coercing, for both
   call sites. Also enforce the entitlement cap client-side; right now line 456
   only sets an HTML max= attribute, which nothing checks.

4. demo-data/ now contradicts the engine. It was not touched when withholding
   tax landed, so demo-data/expected-results/golden-answer-key.json still
   asserts the Harbor case settles expectedCash 191250 / actualCash 189250
   (gross), while the engine computes 162562.50 / 160562.50 (net of 15%
   withholding). demo-data/settlement/expected-settlement.csv carries the same
   stale 191250 for EVT-DIV-001, and the exceptionTask name no longer matches
   the seeded task title.

   Update the answer key and the settlement CSVs so they agree with what the
   code now produces, including the gross, withholding and net figures as
   separate values. This file's whole purpose is to let someone verify the
   calculations independently, so it must be correct.

   Note demo-data/ is documentation only — nothing imports it. Do not wire it
   into the app.

5. Neither declared font is ever loaded. index.html line 18 fetches Inter, but
   src/index.css lines 109-110 declare 'Plus Jakarta Sans' and 'Spline Sans
   Mono'. The app therefore renders in generic fallbacks while paying for an
   unused download. Load the two fonts the CSS actually declares, with the
   weights in use, and drop the Inter link.

   Also in index.html: remove `maximum-scale=1` from the viewport meta (it
   blocks pinch-zoom), and replace the placeholder copy "Update this
   description to reflect the app." in the title and meta description.

6. The README environment table documents 6 variables; the code reads 11. Add
   the missing load-bearing ones with accurate descriptions: SESSION_SECRET
   (the app throws at startup without it), CORPORATE_ACTIONS_POC (without it
   every mutation returns 401 outside Replit), CORPORATE_ACTIONS_ROLE_DIRECTORY
   (required in production or every mutation 401s even for an authenticated
   OIDC user), CORS_ALLOWED_ORIGINS, and OPENAI_API_KEY (notice extraction).
   Mark which are required in production versus POC-only.
